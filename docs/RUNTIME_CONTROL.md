# 采集运行治理

> 面向：在单实例中调整采集速度、资源预算、账号池与代理健康。配置字典见 [CORE_CONFIG.md](CORE_CONFIG.md)，账号注册与登录回调见 [ACCOUNT_RUNTIME.md](ACCOUNT_RUNTIME.md)，后台入口见 [MONITOR.md](MONITOR.md)。

## 1. 启用与配置来源

浏览器身份是独立的档案/绑定服务，不存入 `runtime_policy`。改绑等待发生在任务认领及全局资源放行前，旧任务继续使用冻结快照；账号池选择版本与身份修订分开。明确网站挑战返回 `site_challenge`，本次不立即重试、不换号、不计代理故障；之后仍可由错误队列补偿。详见 [BROWSER_IDENTITY.md](BROWSER_IDENTITY.md)。本次升级还需显式迁移两张身份表。

新项目的站点请求控制、AutoThrottle、资源控制和代理健康默认关闭。账号池只有在业务注册账号、创建池并给任务配置池归属后才参与执行。普通启动不迁移；升级后先运行 `papa migrate`，补齐 `crawler_config.revision`、`crawler_tasks.account_pool` 及 `crawler_account_pools` / `crawler_account_management`。启动会检查运行治理表结构，并读取版本化策略；读取失败或策略非法时拒绝启用采集。

生效顺序为：框架默认 → Go 站点/阶段声明 → `config.yaml` 中显式 `runtime` 字段 → OA 持久覆盖。同一来源内站点覆盖全局默认，阶段字段覆盖该站相应字段。只有显式写出的字段参与合并；`false`、`0`、空池名与“没有提供”不同。清除某项后台覆盖后，继承文件与声明值。

`runtime` 是主配置中的一段，不读取另一个 `configs/runtime.yaml`。修改文件或 Go 声明仍需重启；OA 的“保存并生效”修改数据库策略，立即作用于新请求/新任务。数据库策略使用 `crawler_config` 的独立 `runtime_policy` 键，`sites` 键继续只保存站点快照。

```yaml
runtime:
  defaults:
    request:
      enabled: false
      autothrottle:
        enabled: false
  sites:
    fixture:                    # 必须是已注册站点，示例不应原样加入其他项目
      request:
        enabled: true
        max_inflight: 2
        requests_per_second: 1
        burst: 1
        manual_delay: "300ms"
      stages:
        detail:                 # 必须是本站已注册阶段
          max_concurrent: 1
          delay: "2s"
  resources:
    enabled: false
  proxy_health:
    enabled: false
```

YAML 时长使用 Go 字符串（`"300ms"`、`"30s"`）；HTTP JSON 中 `time.Duration` 是整数纳秒，例如 30 秒写 `30000000000`。OA 表单用秒显示并转换。Go `StageSpec.Delay` 仍支持 `"10s-30s"` 随机区间；运行策略的 `stages.<stage>.delay` 是固定时长。清除覆盖恢复原声明随机区间，页面通过声明数据展示实际范围。

| 可动态调整 | 仍由启动配置/Go 决定 |
| --- | --- |
| 阶段有效执行并发、固定任务间隔、站点请求并发/速率/AutoThrottle | `WorkerCount` 物理 worker 数、`QueueSize`、站点/阶段拓扑、Retry 声明 |
| CPU/内存阈值、任务与浏览器借用许可、站点权重 | 浏览器物理池容量、二进制与网络授权、数据库连接池 |
| 池归属默认值、代理失败阈值与冷却参数 | 账号凭据来源、Login/Check 实现、账号固定代理来源 |

有效执行并发不超过物理 worker 数。降低限额只限制新工作，已有任务和浏览器借用自然完成；在途数暂时高于新限额表示正在收敛，不会强杀实例。Task.Delay/NotBefore 的延迟投递、阶段任务间隔、实际请求间隔是三个不同概念。

## 2. 同站请求预算

目录、详情、内容以及同站不同账号共享一个站点请求控制器。设置 `request.enabled: true` 后，`max_inflight`、固定速率/突发额度与请求间隔共同约束实际 HTTP 交换；仅关闭 AutoThrottle 会回到手动间隔，仍遵守请求硬限制与远端冷却。

AutoThrottle 根据实际交换的响应延迟平滑调整，在最小/最大间隔范围内运行；排除本地许可和认证等待。失败响应不会让它加速。HTTP 重定向及调用方的每次重试都重新申请许可，控制器不会为业务自动重放 POST 等有副作用请求。

429 使用 `Retry-After` 秒数或 HTTP 日期；未给有效值时使用默认冷却。503 仅在带有效 `Retry-After` 时触发这一冷却。等待超出 `retry_after_max` 时进入需确认状态，不把服务端等待截短；后台确认后仍须等完整远端期限，确认不等于立即放行。单个 403、解析错误和网络超时不直接认定账号失效。

请求上必须保留任务传入的 `ctx`。在任务外用 `engine.RuntimeContext(ctx, site)` 显式绑定站点预算。业务自己创建且不走框架受管传输的 HTTP 客户端不自动受控。账号 Login/Check 内自行发出的请求，也应使用传入 context 和框架受管客户端。

| 路径 | 当前覆盖 |
| --- | --- |
| Engine HTML、HTTP/API、增量请求 | 每次实际 HTTP 交换，含重定向与响应体结束/取消释放 |
| 账号 HTTP | Manager 使用的受管客户端；账号认证等待与账号并发不重复计为站点请求 |
| filedown / M3U8 | 框架下载器发出的 HEAD、文件、清单、分片及密钥等 HTTP 请求，需继续传递任务 ctx |
| 浏览器 | 通过框架页面入口创建的当前 page target；第一篇主文档的同源请求及 `PageOptions.GovernanceOrigins` 显式加入的 origin，包括受管导航、XHR、子资源与同范围重定向 |

浏览器治理不是全浏览器网络计量：新 popup target、独立 worker、业务绕过框架创建的原始 Rod page，以及业务重新覆盖 CDP Fetch 处理器的路径不在这一覆盖承诺内。未列入的第三方 origin 不计入目标站延迟。开启请求控制时，受管页面禁用缓存并绕过 ServiceWorker；关闭后恢复浏览器默认行为。代理 CONNECT 健康反馈只能确认隧道建立，不能读取 TLS 隧道内的 HTTP 状态。

带站点治理 context 的受管页面会将后续请求交给当前策略判断；OA 动态启停作用于新请求，不取消已经发出的请求。账号 Render/Capture 的 Block 与 GovernanceOrigins 在 bootstrap 恢复页创建时安装，目标仍必须与账号 bootstrap 同源；治理列表不能扩大账号凭据的可用 origin。

请求总数/速率按站点汇总；阶段表显示任务执行统计，当前没有每阶段请求量明细。请求预算不代替下载器原有的连接并发、分段并发或带宽设置，不能将请求数解释为任务数或下载字节数。

## 3. 单实例资源放行

开启 `resources.enabled` 后，独立采样器采集 CPU/内存，使用高阈值、恢复阈值与连续窗口形成滞回。任务执行与浏览器借用有各自的许可；纯 HTTP 任务不消耗浏览器借用许可。浏览器物理池不足时，不长期占住全局浏览器许可阻塞其他就绪站点。

站点 `weight` / `min_weight` 用于就绪站点间的服务机会分配；空闲份额可借用。最低权重不保证在内存紧急、站点暂停、账号耗尽或远端冷却时仍强行放行。采样失效显示未知，保留保守限额并暂停自动上调；页面关闭不停止采样。

认领前的账号、冷却与资源等待不占任务执行许可。已经认领的任务保留许可直至本次执行结束；执行中遇到后续请求等待也不会被抢占。公共浏览器池单列实际已创建、已借出、等待资源、空闲与物理容量；这些是引擎公共池的受管实例数，不含账号专用池或 Chromium 子进程。全局借用许可则覆盖带治理 context 的公共池和专用池。

这是单实例内的资源控制，关注模块化、背压、崩溃恢复和纵向容量，不依赖多实例协调。

## 4. 账号池与任务补偿

账号按 `(site, account ID)` 注册，池按 `(site, pool name)` 分组；权限不同的账号分入不同池。成员按显式顺序选择备用，哈希索引只用于定位和状态检查，不决定替补顺序。一个账号加入同站多个池时，共享该账号的停用/隔离状态。

健康时每站每池持续使用当前账号，不因请求完成、阶段切换或普通重试轮换。明确失效时，本次尝试直接结束并记录失败，跳过当前阶段立即重试；独立调度器标记旧账号不可选、有限验证备用并发布新选择。任务不在 FetchHandler 内等待换号。已发请求自然结束，旧身份再发请求时会检查选择版本，不能半途混入新身份。

新任务在认领前等待账号就绪，不占全局任务执行许可。当前账号只是并发已满时，等待现有 `Manager.MaxConcurrent` 名额，不把繁忙当作失效。任务的 `AccountPool` 持久化到 `crawler_tasks.account_pool`；页面去重/幂等键不增加账号或池维度。同一已有任务被指定为不同池时返回归属冲突，不新建第二条任务，也不改写旧任务归属。

阶段未指定池时继承站点默认；阶段显式设置空池名可取消该阶段的默认绑定。新任务持久化之前，创建与池删除共享引用保护，避免边删池边插入引用。仍被运行策略或待处理、失败可重投、轮询任务引用的池不能删除；旧 TaskFlow 入口不接受显式账号池绑定。

以后通过错误队列或人工重投补偿，复用原任务记录并取得该池当前账号；更换运行策略的池默认值不迁移已有任务。账号专属资源或游标能否在备用账号继续使用，仍须由业务判断。密码、Cookie、Token 不进入运行策略或任务 Meta。

池成员、当前选择与版本以及账号管理状态分别持久化；凭据仍由现有账号 Store 管理。恢复后重新验证认证状态，不因重启把停用/隔离账号变为可用。冷却到期只允许验证，成功才恢复；恢复不会自动抢回当前账号。详细 API、默认补偿预算和后台动作见 [ACCOUNT_RUNTIME.md](ACCOUNT_RUNTIME.md) §7。

## 5. 代理健康

开启 `proxy_health.enabled` 后，已确认的代理拨号/握手故障和代理认证 407 累积失败；达到阈值进入冷却，失败探测指数增加冷却至上限。冷却到期只允许有界探测，满足恢复成功数后才重新可用。目标站 429/403、普通目标错误与账号过期不会污染代理健康。

代理列表刷新保留仍在列表中的健康记录；移除记录等待持有引用的请求结束后回收。固定出口单独跟踪且状态有界；固定代理失效不改写账号或在途浏览器出口。启用健康后，要求代理的框架请求在耗尽时明确报错，不回退直连。低层 `WaitAcquire(ctx)` 可取消等待；传统 `Next() string` 无法表达耗尽原因，新接入应使用 `Acquire` / `AcquireURL` / `NextChecked` 并处理错误。

管理页提供脱敏标识、最近状态/结果、失败次数、冷却、在途数和固定出口标志。启用只进入探测，不直接置健康；显式探测向已注册站点 BaseURL 发送一次受站点预算约束的 HEAD。状态不包含凭据，也不提供完整代理请求历史；管理动作记录在操作日志。浏览器 CONNECT 与普通 HTTP 的观测边界见 §2。

## 6. OA 保存、重启与运维

“运行监控与报告 → 采集控制”包含站点请求、资源控制、代理健康三个页签；“数据与资源 → 账号池”维护成员、顺序、停用、验证及当前选择。资源控制始终为全局范围。没有采样时显示未采样/未知；页面只读刷新不触发登录或探测。

策略 POST 携带独立的 `revision`，JSON 文档包含 `schema_version: 1` 与 `overrides`，文档内部不重复保存 revision。校验通过后先做数据库 CAS，再发布运行快照；旧 revision 返回 409。首次保存从 revision 0 插入 1；清除覆盖仍是一次递增写入，不删除重建。提交回执不明确时查询服务端核对，不自动重放写操作。

账号池删除保留版本墓碑。旧页面保存不能复活已删除的池；同名重建必须核对删除记录并显式使用最新 revision。运行策略遇冲突时保留草稿，核对后只将本次修改过的字段合并到最新策略，保留其他人的无关改动。

后台持久覆盖跨重启恢复；代理健康读数、请求窗口与资源采样是本次进程状态。账号池切换记录在池状态中保留最近 100 条。任务实际账号/选择版本记录在 `task.Trace.Step`，需开启 `crawler.trace.enabled` 才能在任务追踪中查看；没有另建每任务永久身份历史列。新脚手架默认开启 Trace，其保留期仍由 Trace 配置控制。

所有管理接口沿用令牌鉴权，`server.operation_log` 开启时记录管理操作审计；操作列表和请求格式见 [MONITOR.md](MONITOR.md)。真实网站的账号协议、跨账号幂等性与业务结果验收属于独立业务模块。
