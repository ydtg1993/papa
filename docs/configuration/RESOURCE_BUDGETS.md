# 单实例资源预算与背压

> 面向：配置 Papa 单实例进程资源、处理输入超限和调度积压的宿主开发者。
> 配套：[运行配置](CORE_CONFIG.md)、[任务时间](../runtime/TASK_TIMING.md)、[观测报告](../operations/OBSERVABILITY.md)、[目录职责](../package_structure/README.md)。

资源预算与业务并发配置分开。Config、下载 Overlay、ResumeState 和报告 SourceConfig 各自表达所属组件的参数；预算通过独立类型和装配接口配置。以下上限约束框架管理的数据或令牌，不是进程 RSS、用户插件分配或操作系统文件系统的硬配额。

## 1. 装配入口

在 Run 前配置；Engine 下载预算必须早于 InitDownloaders，调度预算必须早于阶段启动。运行中不热修改预算。

```go
// app 是已经构造好的 *papa.App。
if err := app.UseReportInputLimits(papa.ReportInputLimits{
    MaxEvents: 1024,          // 在线入口槽位上限（仍受内置 1024 上限约束）
    MaxDedupKeys: 256,        // 在线聚合维度上限（仍受内置 256 上限约束）
    MaxRetainedBytes: 64 << 20,
}); err != nil {
    return err
}
if err := app.Engine.SetDownloadResources(
    papa.DownloadLimits{OutputBytes: 8 << 30, Chunks: 100000, Segments: 100000},
    papa.NewDownloadBudget(1 << 30, 64 << 30),
); err != nil {
    return err
}
if err := app.Engine.SetSchedulerLimits(papa.SchedulerLimits{
    Global: 4096, Site: 2048, Stage: 1024, RefillBatch: 64,
}); err != nil {
    return err
}
```

这些不是新增 YAML 键；严格配置解析仍会拒绝未定义键。每个字段未设置时使用有限默认值；不要以负数表示无限。不同独立 Engine 或自行创建的下载器不会自动共享预算，宿主可把同一个 DownloadBudget 传给多个实例的 WithResources。Engine 的 filedown/m3u8 基座及 With 派生实例共享装配的预算。

## 2. 在线观测与离线报告输入

`App.UseReportInputLimits` 作用于在线信号入口和聚合维度：槽位取 `min(1024, MaxEvents, MaxRetainedBytes/64KiB)`，维度取 `min(256, MaxDedupKeys, MaxRetainedBytes/1KiB)`，两者至少为 1。在线不扫描 JSONL、日志或数据库，所以 MaxFiles、MaxLineBytes、MaxBytes、MaxSpoolBytes、MaxDays 不影响在线服务。满载信号可丢弃或截断，报告给出完整性说明；它不承担可靠结算。

在线报告与事件归档在关停时共享最多 2 秒等待预算，超时不会扩大业务资源的存活边界；Engine 和宿主业务是否排空仍独立决定共享依赖能否关闭。Trace/页面归档在 worker 尝试收尾中写入，不属于此在线 obs 预算。

下面的输入限制用于显式离线调用 `obs.LoadSourcesContext` / `obs.ConsumeDailySources`，参数类型为 `obs/inputbudget.Limits`。它们不从 App 继承在线配置。

| 项目 | 默认上限 | 口径 |
| --- | --- | --- |
| 文件数 | 1024 | 发现/读取输入文件 |
| 单行 | 1 MiB | 物理行字节，包含换行，解码前检查 |
| 扫描字节 | 256 MiB | 解压后的输入，不以压缩文件大小代替 |
| 事件数 / 去重键数 | 各 250000 | 事件额度计窗口内重复行；精确去重，不改为近似算法 |
| 保留编码内容 | 64 MiB | 用于限制事件/日志输入驻留，Go 对象开销另计 |
| 临时分桶 | 512 MiB | 临时报告输入，不是最终报告目录配额 |
| 日期数 | 366 | 单次逐日处理的日期数量 |

事件与日志分别计算扫描预算，两类原始源合计最多各自上限之和；不是跨报告任务共享配额。逐日事件保留内容按日限制，去重键与临时分桶按整次操作限制；日志保留内容按所有窗口合计限制。正常、错误和取消会清理临时分桶，进程被强杀仍可能遗留有界临时文件。

`obs.LoadSources` / `obs.LoadDailySources` 使用默认预算和后台 context。需要取消和自定义限额时使用 `obs.LoadSourcesContext` / `obs.ConsumeDailySources`；底层 eventlog.ReadContext、logidx.BuildContext 使用同一输入预算类型。逐日消费先校验并准备有界输入，再逐日分析；不要在 consume 回调中自行累计全部 Sources。

离线输入超限可通过 errors.Is(err, inputbudget.ErrLimit) 判断，不能把部分事件当完整总体生成“验收通过”。离线调用向调用方返回错误，CLI 据此失败；已有产物不因输入预检失败被覆盖。报告写入仍按既有单份文件规则，不承诺四份产物或多天报告为同一事务。

离线 Timeout 是合作取消预算，覆盖输入读取和分析；无法强制打断用户 Section 或底层不合作 I/O。离线调用方自己拥有所传数据库等依赖和调用生命周期，不将离线分析接入爬虫执行或关停链。

## 3. 下载输入与资源

| 项目 | 默认上限 |
| --- | --- |
| 续传状态文件 | 16 MiB |
| 播放列表 | 8 MiB |
| 单媒体段 | 64 MiB |
| init 段 | 16 MiB |
| AES key | 16 字节 |
| 单产物 | 8 GiB |
| 文件分片 / 媒体段数 | 各 100000 |
| 共享内存预留 | 1 GiB |
| 共享临时磁盘预留 | 64 GiB |

使用 errors.Is(err, middleware.ErrResourceLimit) 识别本地超限。调整输入尺寸或预算前盲目重试通常不能解决；超限不作为坏续传状态自动清除后重下。断点格式由下载包拥有，宿主不应直接改写。filedown 只接受当前 v2 位图格式；m3u8 接受当前写入器仍使用的 v1 状态封装和 v2 位图格式。无版本旧 JSON、filedown v1 和未知版本明确返回错误，不执行旧状态升级或静默重下。

预算为非阻塞准入：不足时返回明确错误，不让已占 worker 的调用无限等待资源。临时磁盘会统计已登记续传根中的保留文件并预留本次工作；活动文件和预留可能保守重复计算，嵌套目录也可能重复计入。因此默认单产物 8 GiB 不表示能同时接受 64 GiB / 8 GiB 个下载。

下载未成功时保留可恢复分片；保留模式也会占用磁盘。框架不按年龄删除活动状态，用户仍需规划续传目录容量和清理不再使用的数据。输出目录中既有成功产物、其它进程的写入和用户插件内存不属于可强制限制的配额；需要操作系统/卷级限制时由部署负责。

非加密媒体采用有界流式临时写入，限速位于读取循环；加密媒体保持有界完整缓冲与解密验证，不能以截断内容换取“成功”。检查点由单写者合并完成通知，最终等待 flush，保留原输出路径锁。私有 v2 位图消除重复路径；m3u8 在分片路径列表长度与总段数不一致时写入 v1 封装，其余状态使用 v2；每次合并快照仍为 O(N)，不是增量日志或总写入 O(N) 保证。M3U8 收到的重试字节也保守计入单产物额度。

文件产物先写暂存再发布，保留已有普通文件权限位，新文件为 0644；不承诺 ACL/属主及断电持久性。已有 OutputSegments 按文件重命名，仍不承诺整目录事务。FFmpeg 的 -fs 可能按包稍超阈值，最终尺寸校验拒绝过大产物发布；绝对物理磁盘上限需要卷级配额。

## 4. 调度工作集

预算针对驻留 Task 引用，包括排队、运行、spill、delay 与取出待回灌项。默认全局 4096、每站 2048、每阶段 1024，补充批量 64，延迟预取窗口 1 分钟。Task 的 URL、Meta 等大小仍可不同，引用数量不是精确字节上界。

回灌使用单批 ID 查询及 100ms 时间片/context 截止时间；数据库持续超过该查询预算会延迟补充，应观察超时日志、查询计划和积压延迟。

持久 pending 是工作事实，内存队列是有限工作集。连续补充独立于可选启动 RecoverQueue；远期任务保留在数据库，到窗口内再准入。达到内存预算不得把已接受任务标失败；提交者也不能在 worker 内阻塞等待同一池释放容量。未持久化或含未交接状态的工作必须先明确责任，不能无声丢弃。

数据库认领、轮次/版本和 NotBefore 条件仍决定是否执行，预算不替代 CAS。暂停站点不应持续耗尽其它站的补充机会；取消停止新读取，已准入收尾仍由既有等待协议负责。SchedulerResidentCount 用于观察引用数量；数据库 backlog 与内存 resident 应分开理解。

## 5. 部署验收

根据任务负载和硬件逐步调整预算。至少观察进程 heap/RSS、resident 与 durable backlog、最老待执行延迟、超限错误、报告扫描量、临时磁盘、DB 查询率和关停耗时。提高上限会提高最坏资源成本；有限默认值不等于已完成生产容量标定。

验证以合成 fixture 和独立测试库为准；大规模长稳、断电、磁盘满、其它 MySQL 版本及真实业务插件仍需要部署验收。保持单实例大单体，不引入分布式租约或多实例协调。

## 6. Trace 文件预算

Trace 默认 errors，all 保留所有尝试，off 不分配缓冲；未关闭时，单个尝试只保留最多 500 步、约 512 KiB 的框架缓冲，步骤数据最多 16 KiB；超限保留尾部并标记截断。数据预算不等于整个进程 RSS 上限，业务构造 data 的成本及自定义序列化代码不属于框架分配预算。

文件默认最多 4 MiB/文件、256 MiB 总量、10000 个文件；`crawler.trace_files` 可覆盖。容量满拒绝新证据并告警，不淘汰未过期证据，不改变任务结算。默认七天保留期按 JSON 的记录时间判断，清理不因查看而续期。清理按文件释放 Store 门，损坏文件保留并汇总错误，其它有效过期记录继续清理。

首次盘点有有限目录与文件数安全上限；调低预算后可在 `max(当前配置,默认值)` 的恢复范围内读取/清理，超出该范围需先恢复足够的预算。目录必须由一个 Store 独占，外部移动/改写文件需停止组件后操作。崩溃遗留 `.pending` 不作为已发布证据读取，但计入配额且不自动删除；需要人工检查处理。损坏文件同样可能持续占用容量。

写入采用文件 Sync、Close、Rename，保证完整文件发布；不承诺目录 fsync 或断电恢复。单次尝试尚在内存时进程被杀，其步骤会丢失。读写串行协调，慢盘会延长收尾；context 能取消等待和文件操作之间的工作，不能强制打断正在执行的 OS 文件系统调用。应额外观察 Trace 写入告警、目录尺寸、剩余磁盘及关停耗时。
