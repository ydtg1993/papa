<!-- version-scope -->
> **适用版本/阶段：Papa v4 演进过程中的历史工作区快照（具体基线以正文为准；未记录精确发布版的条目不推定版本号）。**
> 审查结论、路径、接口和测试结果仅适用于当次代码与环境；旧兼容约定不延续为当前契约。 本文为设计/计划记录，不能仅凭计划步骤或复选框认定已实现或已验收。 当前使用方式以 [v4 手册导航](../../README.md) 为准。

**Goal:** 后台能从一次熔断直接定位短时集中失败的类型、证据和验证方向。

**Architecture:** engine 在既有 breakerMu 下保留有界脱敏样本并冻结现场；obs/incident 是不依赖引擎的纯分析器；后台按需生成分析并导出。历史报告复用事件流和同一分析器，不扫描线上日志，不访问外部 AI。既有事件流负责历史持久化，实时列表明确限定本进程。

**Tech Stack:** Go、现有 Monitor API/对话框、obs 报告、Go tests、Node 前端行为测试。

用户已批准方案并要求实施；当前工作区执行，不执行 Git 写操作。

- [x] 新增 obs/incident：按阶段、kind、保留状态码的错误模板分组；有界样本、脱敏、证据/假设分离、报告渲染和测试。
- [x] engine 集成：每站最近 256 条样本，最多保留全局 32 次熔断且每站 4 次；恢复只清采样窗口，不删已冻结现场；窗口边界、恢复和并发回归。
- [x] Monitor 增加鉴权只读分析接口，站点卡片及熔断提示增加入口；显示排行、详情、历史、复制和下载；错误/空态/陈旧响应测试。
- [x] obs/analyze 关联熔断前窗口内事件，复用分析器输出报告；旧事件缺乏窗口时明确降级；不臆测阈值偏低。
- [x] 文档同步并运行 gofmt、定向与全量 test/vet/build、相关包 race。

边界：采样截断及缺失必须披露；百分比以采样失败数为分母，不称作请求失败率。诊断不自动恢复、不修改任务、不取消在途工作、不增加数据库迁移。跨进程历史以已有 obs 事件和生成报告为准。

验证结果：go test ./...、go vet ./...、go build ./... 通过；CGO_ENABLED=1 go test -race ./engine ./obs/incident ./obs/analyze ./admin/server 通过。真实 Chromium 的 TestBreakerAnalysisRealBrowser 在 1100px 和 390px 视口通过，核验了历史切换、复制脱敏报告、证据纯文本和 Escape 关闭。Node 行为测试覆盖旧响应、关闭/身份失效后的响应和复制/下载隔离。最后补充历史报告表格与浏览器日志动态前缀归并后，obs 全包、后台包及新增归并/引擎定向测试再次通过。

保留边界：只实现 v4；未更新 crawler 的 v3 依赖。实时列表不跨重启，历史依赖既有事件与报告配置；未执行真实业务采集或部署，不改数据库结构。
