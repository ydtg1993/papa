用户已授权修复五项问题、分离报告与控制、区分重试和强制解除；本轮直接施工，仅修改工作区，不执行 Git 写操作。

设计采用最小职责拆分：原有 smartBreaker 保留锁、调度与写入门槛；独立 Recovery 数据保存原始标识和控制字段，Lifecycle 只作为报告投影。持久快照同时保存控制、Detector 失败窗口及报告，在同一事件行按修订号原子更新，不增加控制器或报告体系。报告裁剪、脱敏不修改控制字段。旧快照缺少窗口时保留已知失败下界并转人工，不伪造已验证恢复。

- [x] 将隔离复现转为正式回归：时间线截断、中文阶段标识、超时收尾、obs 遗漏。
- [x] 分离控制与报告，取消报告 Limited 对健康判断的影响，所有中止路径关闭阶段检查。
- [x] 保存并恢复 Detector 失败记录、容量保护和去重身份；重新验证全部阶段，恢复预算不随重启延长。
- [x] obs 查询数据库中的活动事件及窗口相关事件；日志仅补离线引用，按最后出现去重，有上限时明确提示。
- [x] 普通恢复重新验证整站并保留失败数；单独提供强制解除 API、后台入口和操作日志。旧探针返回不能污染新一轮。
- [x] 空闲阶段方案写入 BREAKER：显式声明完整只读语义验证能力，不通过队列为空自动豁免真实任务门槛。本轮不自动生成业务任务。
- [x] 同步 BREAKER、MONITOR、RUNTIME_CONTROL、DEVELOPMENT、公开接口文档与变更说明。
- [x] 运行定向及完整测试、race、真实隔离 MySQL、前端验证；复查锁顺序、旧回调、写入失败及重启路径。

备选方案不采用：新建恢复管理器会增加重复状态；用报告样本重建精确失败窗口会因裁剪丢计数。空闲阶段也不自动重跑已完成任务，避免业务写入及子任务副作用。

验收与边界见 `docs/history/reviews/2026-11-12-breaker-site-recovery-review-fixes.md`。空闲阶段仅交付方案，未启用行为变更。
