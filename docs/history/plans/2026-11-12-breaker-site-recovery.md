按用户最新确认的规则施工，覆盖此前局部自动恢复设计；仅改工作区，不做 Git 写操作。

目标：局部成功只作为证据，全部阶段验证正常后才恢复整站、清空运行计数，obs 能展示整个暂停与恢复过程。

设计：触发事件始终约束整站。枚举站点注册阶段，逐阶段只读语义试探，空 stage 的探针作为逐阶段回调的兜底，不能用一次首页成功代表所有阶段。一次探测预算代表完整一轮阶段检查。全部通过才放行整站限量真实任务，每阶段至少一次本轮任务成功、观察期完成且全站在途为零后确认恢复；没有任务/没有探针的阶段不能默认为通过。混合观察允许所有阶段都有至少两个独立任务成功后直接完成验证。最终报告保留清零前计数，保存确认前不全量放行。人工强制解除不代表健康证明，不清计数，人工暂停仍仅在进程内有效。

报告沿用 Lifecycle：增加有界阶段验证进度和带阶段/轮次/计数的时间线，记录等待、暂停、试探开始和结果、重试、限量任务验证、等待在途结束、恢复清零、人工操作及重启。obs 通过统一事件 ID 读取同一份报告；后台展示阶段进度与时间线，无新增统计体系或表。
