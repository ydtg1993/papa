# Papa v4 任务时间与身份实施计划

<!-- version-scope -->
> **适用版本/阶段：Papa v4 演进过程中的历史工作区快照（具体基线以正文为准；未记录精确发布版的条目不推定版本号）。**
> 审查结论、路径、接口和测试结果仅适用于当次代码与环境；旧兼容约定不延续为当前契约。 本文为设计/计划记录，不能仅凭计划步骤或复选框认定已实现或已验收。 当前使用方式以 [v4 手册导航](../../README.md) 为准。

用户已审阅方案并明确要求先施工；熔断单独延期。禁止 Git 写操作，直接改工作区。

目标：任务最早执行时间跨重启保留，最近执行时间可查询，站点/阶段/资源身份成为一致的去重契约。

- [x] 时间：模型增加 not_before、delay_ms、last_started_at、last_finished_at；Task 转换和批量插入跟进；相对延迟首次持久化按数据库时钟计算。
- [x] 调度：所有恢复/回灌/加急及认领路径遵守时间；不反复重算 Delay；单条插入后回读失败显式处理。
- [x] 执行：每次 Handler 调用记录开始结束，数据库失败不静默忽略；保留已有轮次和重试语义。
- [x] 身份：core 实现无歧义编码、URL 规范化和 hash；Task ResourceID 优先，统一 Unique 与模型索引。
- [x] 迁移：新唯一索引前检测历史冲突；旧 URL 唯一索引不再限制不同 ID；禁止隐式合并历史行。
- [x] 回归：身份规范、重复/批量/冲突、跨重启延迟、认领守卫、时间写失败、SQL 形状、fake 列及真实 MySQL。
- [x] 文档：Fetcher、落库、恢复、迁移、后台、开发及变更记录同步；熔断文档标明未实施。
- [x] 验证：gofmt、相关测试、全量测试、vet/build、定向 race；有本地配置时只创建随机独立测试库并清理。

分工：identity 负责身份与迁移；timing 负责时间与执行路径；主协作者负责熔断文档、集成审查与最终验证。共享文件仅按职责分别修改，及时同步。
