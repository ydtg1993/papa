## 分工与验证

- [x] D1–D3：filedown/m3u8 内部有界调度、派生客户端时限隔离、合并到临时文件后发布。回归覆盖极大长度取消、并发上限、共享代理不同超时、旧文件保留和成功替换；定向 test/race。
- [x] D4–D6：admin/reports 从 rooted 句柄校验/读取；obs/report 安全目录名；cmd/papa 显式历史生成保留产物。回归覆盖链接、特殊目录段、历史日期和默认保留行为。
- [x] D7：engine 批处理在查询和每条准入前检查生命周期；查询/重置传 context；已完成条件重置的任务保持既有收尾。回归覆盖零暂停取消、同批停止准入、等待在途回调、已取消不写库。
- [x] D8–D9：Engine 认领后生成执行身份，同轮重试共享；归档使用执行身份；Trace 增加执行身份，兼容旧数据、返回最新执行及截断提示。模型变化遵循显式迁移，绝不自动迁移业务库。
- [x] 集成：审查并发及文件发布边界、结构说明/使用手册/诊断报告同步。
- [x] 验证：gofmt、定向回归、全仓 test、vet、build、全仓 race；浏览器相关重跑串行，避免多个全仓批次竞争浏览器；明确外部 MySQL/ffmpeg 验收边界。

各子任务按“复现失败→实现→定向验证→集成复核”推进。新增职责放在原拥有者中，不将实现搬进 App 或通用 utils。最终报告记录准确命令、结果和未验证项。
