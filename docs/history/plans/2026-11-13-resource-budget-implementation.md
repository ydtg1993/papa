> 执行：按已批准的资源预算方案分域实施、逐项复核和集成验证。禁止任何 Git 写操作，不创建或切换工作树。

**目标：** 输入有预算、取消能传播、持久任务内存工作集有界且持续补充，降低检查点和报告读取放大。

**职责：** obs 负责输入和逐日消费，reportrunner/CLI 仅编排；下载包拥有流式传输、续传与预算；Engine/scheduler/taskstore 拥有调度准入、内存成员和持久发现。公开现有类型布局不轻易增加字段，采用新类型/方法。三个子计划记录各自实际文件与测试。

**技术：** Go、GORM/MySQL、标准库 context/io、仓内假库与隔离 MySQL 回归。

## 阶段及检查点

- [x] 输入与取消：obs 行/解压字节/事件/文件预算、m3u8 角色响应和片数预算、旧续传状态预算；精确限额和超一单位回归，错误不截断伪成功。
- [x] 工作集：持久 pending 持续扫描先成立，再设 spill/delay/pool 成员准入；暂停/公平/轮次/数据库不确定写/内部提交无阻塞；真实 MySQL 验证，不修改业务数据。
- [x] 降低放大：逐日消费不聚合全部日报；有界媒体流式读写；单所有者检查点合并并排空，兼容旧 JSON。
- [x] 跨域复核：旧公开 API/配置布局、取消入口、停止依赖生命周期、预算释放与错误分类。回归原 D1–D9。
- [x] 文档：按实际实现同步 package_structure 七册涉及章节、使用手册和诊断资源预算报告，列明默认值、超限行为及剩余边界。
- [x] 验证：各域测试和 race；整体 go test ./...、go test -race ./...、go vet ./...、go build ./...；新增调度实库测试在随机独立库执行；文档链接/源码职责覆盖/git diff --check。
