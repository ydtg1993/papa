## 目标与职责

Trace 仅使用文件。默认保留失败、panic、显式 Fail/Warn 的尝试；干净成功不落盘。正常关停取消本身不触发保留。下一次执行主动追踪接口覆盖该轮所有重试，后台按钮另行开发。保留现有公开步骤/查询值布局。默认保留七天。

- `internal/tracestore`：版本化记录、受限路径、原子发布、容量、查询、过期清理；仅依赖标准库及 core 值类型。
- `engine`：异常保留策略、有界尝试缓冲、手动选择状态、执行身份与生命周期装配；不执行 Trace SQL。
- `config`：新增独立 `crawler.trace_files` 目录与预算，原 `TraceConfig` 布局不变。
- `internal/database` / App：移除 Trace 常规迁移与就绪探测，不自动删除旧表。
- `admin/tasktrace`：沿用查询接口，明确最新保留证据不等于当前任务结果。

## 边界

旧 SQL 历史不回退读取、不自动导出；旧模型兼容声明仍可保留。磁盘满、损坏或超额导致证据写入告警，不改变任务结算。每次尝试结束同步发布文件，执行轮次目录汇聚各尝试，避免重写整个执行。容量上限与保留期共同生效。断电持久性及真实高负载验收不以单元测试替代。
