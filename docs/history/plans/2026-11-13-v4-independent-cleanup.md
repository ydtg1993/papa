# V4 Independent Cleanup Implementation Plan

<!-- version-scope -->
> **适用版本/阶段：独立 Papa v4 清理阶段及正文追加的验证批次。**
> 不兼容 v3 及更早版本的边界继续适用；具体测试结果、耗时和遗留风险仅对应正文记录的代码与环境。 本文为设计/计划记录，不能仅凭计划步骤或复选框认定已实现或已验收。 当前使用方式以 [v4 手册导航](../../README.md) 为准。
<!-- /version-scope -->


**Goal:** 用户明确要求 v4 独立版本，不再维持 v3 或更早版本兼容入口及废弃实现。
**Architecture:** 按模块所有权删去历史双轨；当前 v4 门面、平台支持、背压和取消/恢复契约保留。旧格式明确拒绝，不能靠丢弃损坏数据继续运行。只修改 Papa 工作区；不执行 Git 写操作或业务库清理。
**Tech Stack:** Go、MySQL schema 声明、内嵌 JS、Go/Node 回归。

- [x] config/core/models：移除 Trace enabled 兼容与 SQL Trace 模型/检查；删除任务旧身份字段和回填迁移；保持 v4 identity 唯一性。
- [x] engine/internal：移除 core 历史别名转发和旧方法，调用方使用所属包；熔断仅恢复当前控制快照，旧格式明确报错；保留当前恢复/关停状态。
- [x] admin：移除查询双轨和无 context 适配，核实前端/Oao 的实际版本契约后清理历史桥。
- [x] pkg/obs：移除代理吞错 API、无效熔断配置、存储旧入口；当前下载断点和平台协议支持不机械删除。
- [x] cmd：只支持 v4 工程与当前目录布局，旧模块拒绝保护保留，移除旧目录迁移适配。
- [x] 文档：各模块列出删除/保留依据，更新结构职责与当前API/配置，历史报告标明被本轮结论取代。
- [x] 验证：定向回归、全量 test/race、vet/build、脚手架构建；未验证真实数据库/生产负载如实记录。
