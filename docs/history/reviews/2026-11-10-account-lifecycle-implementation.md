## 实测中发现并修复

- 真实 MySQL 12 个并发策略保存触发 `Error 1213 (40001): Deadlock found when trying to get lock; try restarting transaction`：归档前先取得策略行排他锁，避免 INSERT SELECT 共享锁升级死锁；同版本唯一赢家，历史写入失败回滚策略。
- 已有池从未切换时 history 为 null，浏览器报 `Cannot read properties of null (reading 'length')`：按空记录展示。
- 登录方式无 Fields 时仍须可选；延迟旧进度和画面响应不能串入新过程，关闭页面不被旧请求重开。
- 新增表接入框架迁移/只读目录，凭据文件及登录输入引用不进入只读投影。
- 默认关闭的账号预算不得引入每操作全局数据库串行写；持久计量仅在明确开启时生效。
- 纯计量写入不能让 OA 管理快照不断过期：新增最近控制变更版本，允许计量期间的管理提交，仍拒绝真实健康/政策冲突，存储 CAS 保持严格。
- 保存时冻结提交快照，策略冲突展示完整备用设置；部分补偿失败显示每条结果并要求重新预览。

## 部署边界

普通启动不迁移，本轮没有迁移业务库。升级前使用业务原有显式迁移入口；标准脚手架为 `go run . -migrate` / `papa migrate`。新增 `crawler_account_profiles`、`crawler_runtime_policy_history`，并扩展任务补偿与关联字段。测试只创建自有随机临时库并清理。

真实网站登录协议由独立业务 Provider 实现。此次验证使用合成登录页面和本地 Chromium，不能当作任意真实网站登录或重型反爬通过证明。远程操作采用鉴权的受控 JSON 画面与输入通道，不提供原始 CDP，也不实现通用验证码识别。

健康/切换记录及账号尝试均有界，不是永久审计历史。启用日额度、操作间隔或 TrackUsage 后按操作持久预留，需要计入数据库成本。无法安全强杀忽略 context 的业务回调；超时排空返回失败并保留其依赖。
