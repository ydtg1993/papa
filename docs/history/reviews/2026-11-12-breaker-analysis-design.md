## 目标与边界

在单实例内识别短时间错误爆发：同类错误迅速保护，混合错误有界分析，输出可解释的故障报告。不引入分布式协调，不自动修选择器、猜新域名或修改业务任务身份。

保留 Window 与 Threshold（窗口内终态失败任务数）。成功数、失败率、连续失败和错误分布是辅助证据，不能抵消失败数或替代硬性保护。

## 术语与统计口径

| 术语 | 口径 |
| --- | --- |
| 终态失败 | 重试耗尽、或判定不可重试后落 `failed` 的任务。是熔断计数的**唯一输入**。 |
| 请求 / 任务 / 任务轮 | 一次 HTTP/浏览器请求、一条任务、一轮任务的 handler 生命周期是三个量级。熔断只数任务轮，不数请求与 attempt。 |
| 分类（category） | 回答错误**性质**（DNS、TLS、429、解析、限流、本地故障……）。 |
| 指纹（fingerprint） | 回答是否**同一故障**。分类与指纹正交：同一分类可含多个指纹，同一指纹必属同一分类。 |
| 短窗口 / 常规窗口 | 线一、线二用短窗口（敏感、快速）；线三用常规窗口（兜底、稳定）。二者默认值待校准。 |
| 受影响范围（scope） | 暂停/限制的最小作用域：站点、阶段、路由或账号，由指纹维度决定，宁可小不可大。 |
| 观察期 / 冷却期 / 试探 / 小流量恢复 | 恢复状态机的四个阶段，见「恢复状态机」。 |

### 计数不变量（硬约束，任何实现不得违反）

1. **只数终态失败任务**：重试 3 次只记 1 次；不按 attempt、请求、失败率或连续失败计数。
2. **任务级去重**：同一任务的请求或 Handler 重试不冒充多个失败任务。
3. **单调性**：成功数、失败率、连续失败、错误分布是**证据**，只能增加信息、不能扣减失败数，也不能替代硬性保护。
4. **三层统计分离**：请求级统计供限流与诊断；任务级统计记录每轮任务的成功/终态失败；试探单独统计，不与正常流量混算。
5. **时期标注**：并发在途请求、观察期、恢复前后的样本必须标明所属时期，禁止跨期混算。

## 错误分类与指纹

分类回答错误性质，指纹回答是否为同一个故障。优先采集结构化错误类型、HTTP 状态、失败环节及业务声明的稳定校验码，例如 structure:title_missing。

指纹以失败环节、类别、稳定错误码或校验规则及必要范围组成，不直接比较包含 URL、时间戳、任务 ID 的整段文本。文本归一化只作兜底，不粗暴删除数字。URL、账号、代理出口、任务 ID 和阶段单独作为关联维度，避免将共同故障切碎。

### 指纹优先级链（逐级回退）

```
指纹 = 优先取结构化稳定键，上一级缺失或不可用时才回退到下一级：

L1  业务声明的稳定校验码（如 structure:title_missing）       ← 最稳定，优先
L2  失败环节 + 类别 + 稳定错误码 / HTTP 状态                   ← 结构可靠
L3  文本归一化（Template，保留数字、只归一化 URL/UUID/任务ID/时间戳）← 兜底

不进入指纹、但作为独立关联维度：URL、账号、代理出口、任务 ID、阶段。
```

约束：L3 归一化绝不删除数字（HTTP 403 与 429 必须分开）；L1 缺失时不得伪造；同一故障因 URL/账号差异被切碎时，须靠关联维度归并，而不是靠更粗的文本模板。

## 限流与 AutoThrottle

发现限流 → 检查 AutoThrottle 是否开启 → 开启时反馈并自适应降频；关闭时不自动启用、不自适应调参。请求控制总开关 `request.enabled` 继续约束自动调节。具体实现对 429，以及带有效 Retry-After 的 503，增加请求间隔（通常翻倍、零间隔至少增加 1ms，不超过 `max_delay`），拒绝响应再快也不能让它加速。

两种情况下均尊重 429/503 的有效 Retry-After（秒数或 HTTP 日期），即使请求控制总开关关闭，也设置站点最早请求时间；HTTP、浏览器的普通请求和试探均不能提前放行，较短新期限不能覆盖较长旧期限。没有有效头且 AutoThrottle 关闭时，沿用固定限速与重试退避，不添加隐式默认冷却；仅请求控制与 AutoThrottle 都开启时保留 `retry_after_default` 的 429 冷却。超过 `retry_after_max` 转为需确认，但确认仍不能缩短远端期限。一次 429 不直接认定宕机。等待在请求放行处协调，避免每个 worker 独立长睡；请求限流计数与终态任务熔断计数分离。

## 触发算法：三条保护线

三条线是**独立的触发谓词**，响应速度递减、证据要求递增。它们共享同一套滑动窗口与指纹聚合基础设施，仅在窗口长度、阈值、作用范围上不同。**触发与归因始终解耦：先停（同步、锁内完成），再分析（后台异步）。**

```
线一　同指纹爆发（最快，证据最单一）
  输入  短窗口 W_s 内、按指纹分组的去重终态失败任务
  触发  ∃ 指纹 f：distinct_tasks(f) ≥ F_threshold
  动作  立即暂停受影响范围 scope(f) 并冻结证据，不等待分析报告
  范围  由 f 的阶段/路由/账号维度确定的最小范围

线二　混合错误总量（观察，非停机）
  输入  短窗口 W_s 内全部去重终态失败任务
  触发  distinct_tasks(全部) ≥ T_threshold，且无单一指纹达线一阈值
  动作  进入异常观察：限制新任务放行 + 限制在途规模，执行限时关联分析
  说明  此保护限制**不是**自动开启 AutoThrottle，必须独立展示
  升级  观察期内线一或线三命中 → 立即升级，不等待分析期限结束

线三　硬上限（兜底，最稳）
  输入  常规窗口 W_r 内全部去重终态失败任务
  触发  distinct_tasks(全部) ≥ H_threshold
  动作  原因未明也执行暂停，报告标「原因待确认」
```

短窗口、常规窗口、最小样本量、同指纹阈值、硬上限及观察预算需通过合成故障和历史事件回放校准，尚未确定默认数值。算法采用规则、滑动窗口、指纹聚合与有界状态机，不使用不可解释评分或大模型直接决定熔断。

## 范围与关联分析

| 现象 | 动作与证据限制 |
| --- | --- |
| 同阶段同规则结构错误爆发 | 先暂停阶段；可能模板变化、登录页或异常响应，不能只凭节点缺失定因 |
| 零散 404/410，其他页面正常 | 单任务失败，不直接全站暂停 |
| 同路由大量 404 | 暂停受影响阶段检查路由、迁移或下架；不等于站点宕机 |
| 429、503、超时混合爆发 | 对照请求量、Retry-After 和降频后变化，分析限流或过载 |
| 多阶段连接错误 | 分析站点、代理出口及本地网络；必要时站点保护 |
| 错误集中于账号 | 对照认证证据隔离账号；403不是失效或反爬的充分证据 |
| 数据库、磁盘、浏览器启动异常 | 本地运行故障，保护依赖资源，不误记为目标故障 |

允许多个原因并存。其他阶段成功不掩盖某阶段持续失败；成功样本用于缩小范围而非扣减失败数。HTTP 200 不等于语义正常。关联报告分别展示事实、支持的假设、反证及缺失信息。

## 恢复状态机

站点级状态机，每个状态迁移都要过「所有权校验 + 预算校验 + 持久化」三道闸。

```
Normal ──线二命中──▶ Observing(限制准入、分类观察)
Normal ──线一/线三命中──▶ Cooldown(立即自动暂停)
Observing ──线一/线三命中或观察结束──▶ Cooldown
Cooldown ──有界只读试探──▶ Probing
Probing ──对应故障类型的语义校验通过──▶ Ramping(小流量)
Ramping ──稳定观察通过──▶ Normal

Probing ──试探失败──▶ Cooldown（再次暂停并延长冷却）
Cooldown/Probing/Ramping ──预算耗尽──▶ Manual（保持暂停，转人工）
```

守卫与约束：

- 人工暂停不被自动解除；只能恢复本次自动保护所拥有的暂停范围（**所有权校验**）。
- 试探受并发、次数、超时、轮次、总时长及 Retry-After 约束（**预算校验**）。
- 不重跑完整 Fetcher，不执行落库、下载、子任务派发。框架提供网络检查，业务提供只读语义校验。
- 结构故障没有对应语义校验时，不凭 200 自动解除。
- 按假设选目标：失败页面、同类已知正常页面与其他路径有界对照；不全站扫描。
- 恢复限制流量与并发，不清空证据后一次释放积压。混合故障分别验证主要错误组。
- 故障事件、冷却期限、自动暂停与试探进度持久化，重启不直接全量放行（**持久化**）。

## 报告生命周期

复用 obs/incident，不另建独立报告系统。

| 阶段 | 生成时机 | 内容增量 |
| --- | --- | --- |
| 初始报告 | 首次保护触发 | 现场冻结 + 事实 + 触发规则 + 初步指纹分布 |
| 过程报告 | 追加降频、试探、恢复证据时 | 动作、Retry-After、每轮试探、积压变化 |
| 最终报告 | 恢复成功或预算耗尽转人工时 | 结论 + 建议 + 完整时间线 |

包含事件 ID、时间线、影响范围、触发规则、窗口起止、阈值和实际数量、成功失败分布、指纹分布、脱敏样本及归档引用、AutoThrottle 开关和调整过程、Retry-After、每轮试探、动作、积压、最终状态及建议。

结论区分服务不可用、疑似迁移或下架、解析失效、限流、账号权限、本地故障和证据不足，不一律命名为宕机。报告持久化失败必须可见并重试。

| 滑动窗口 + 终态失败计数 | `internal/breaker.Detector`（唯一终态结果与分类检测记录） | 短窗快速保护、混合观察及整站硬阈值已接入；恢复判据仍需修正 |

## 验收场景

- 同指纹短时爆发快速保护，重试不虚增不同失败任务数量。
- 混合错误受限观察，硬阈值保底，不无限分析。
- 大量成功不抵消局部集中错误；零散 404 不误判全站宕机。
- AutoThrottle 关闭不被开启，两个开关状态均遵守 Retry-After。
- 结构校验失败不能被首页 200 掩盖；混合原因分别验证。
- 人工暂停不被恢复，试探无业务副作用，恢复不释放全部积压。
- 进程重启保留保护与排期；预算耗尽保持暂停并生成可解释最终报告。
