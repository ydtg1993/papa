# 三次失败样本验证、小时复查与每日历史验收

<!-- version-scope -->
> **适用版本/阶段：Papa v4 演进过程中的历史工作区快照（具体基线以正文为准；未记录精确发布版的条目不推定版本号）。**
> 审查结论、路径、接口和测试结果仅适用于当次代码与环境；旧兼容约定不延续为当前契约。 当前使用方式以 [v4 手册导航](../../README.md) 为准。
<!-- /version-scope -->


用户确认：混合错误优先失败任务，至少三个时选三个不同任务，不足时轮换三次；每小时复查通过全部门槛后自动恢复；中断和重启追加进入每日 obs。

实现保持在原 Engine 状态机和 breakerstore 内。混合错误的验证目标与成功证明分开保存；只读探针必须确认指定 SampleID，真实任务通过原版本化重试和认领执行。阶段证明只在本轮有效。小时复查不解除人工暂停、不叠加未退出回调、不补发错过的多个周期。

运行记录以事件内序号写入 crawler_breaker_history，当前快照和追加记录同事务落地。显示最近128条不裁数据库历史；按日报起止时间取当日过程和日初保护状态，不读未来结论。正常停止有记录；下次启动补记异常中断发现，旧范围保留在历史。新表需要显式迁移。

验证包括三个不同样本、少样本轮换、重复回调、指定样本不被普通成功替代、保存失败时保护、小时自动恢复、人工暂停、未退出回调、重启时间计划和历史范围；真实 MySQL 验证任务重试版本、追加超过128条、重复保存幂等、历史失败回滚控制、跨日查询无未来数据。全量测试与 vet/build、定向 race、Node 和 Chrome 桌面/窄屏检查已通过。

复查移除了旧快照按时间查询、旧独立成功阶段推导及其序号。新存储积压保护验证过人工暂停锁顺序；不会因积压复活人工关闭事件，也不会在积压时清空失败证据。

限制：业务仍需如实实现完整只读语义；正常写入周期之前强杀仍可能丢失未保存记录，不能事后伪造准确宕机时间。日报单次展示10000条、待写内存4096条均有显式不足标识。没有真实站点验收，没有业务库迁移或部署，没有 Git 写操作。
