## 代码范围

1. 已确定的终态失败先存 Recovery.PendingFailure，完成时间/账号反馈/trace/归档后置；普通中间重试不提前终结。
2. 已存待确认失败不受取消回退影响，不退回 pending。
3. 结算旧结果时先按当前时钟清理统计窗口。
4. 后台结算不伪造第二次任务执行失败事件；失败确认仍写追加历史。

沿用原串行占用、保存确认屏障、报告定时循环和终态条件 SQL。一个 Task 私有布尔值传递最后一次尝试，不增加控制器、表列或新后台循环。

## 持久化边界检查

| 中断/异常点 | 验证行为 |
|---|---|
| 业务已终态，结果快照写失败 | 内存保留、阻止放行，不执行辅助/终态写；存储恢复后只结算 |
| 完成时间反复写失败 | 失败结果已持久；八路结算不能抢在原收尾退出前执行；取消不能退回 pending |
| 结果提交但回执丢失 | 重启读到待确认结果，只确认原轮次 |
| 任务终态提交但回执丢失 | 重启确认同轮 failed，不重复追加错误/补偿版本 |
| 终态已提交、计数尚未保存 | 重启按原轮次结算一次 |
| 计数事务提交前失败 | 保留旧 pending 快照，重启重新确认并幂等计数 |
| 计数事务提交后丢回执 | 重启读到计数和已清除 pending，不再次结算 |
| 正常完成后重启 | 计数不变，阶段成功证明不复用 |
| 数据库行轮次冲突 | 继续保护，不覆盖新轮次 |
| 旧错误已过窗口、进程未重启 | 当前失败数不包含旧错误；历史明确确认结果 |
| 普通重试后成功/耗尽/panic/纯取消 | 分别校验是否建立失败意图、失败次数与执行次数 |

测试使用 handler + 隔离 MySQL，在真实事务提交前后注入错误，重新创建 Engine 从留下的数据库状态恢复；不是操作系统级 kill -9/断电测试。已有存储/每日历史回归补充历史原子性与跨日查询，未做真实站点故障演练。

## 可保证与不可保证

已提交的 PendingFailure、同轮终态和计数检查点可跨重启接续；两个事务之间依靠原轮次 CAS 和待确认快照幂等，不声称跨存储原子提交。若数据库连待确认结果都无法保存，运行中保持阻塞，但进程强杀无法保住从未持久化的错误原文。

执行事件日志不是事务型账本，进程中断可导致不完整；实际任务终态与追加式熔断历史作为结算依据。后台结算不算新的业务执行。

## 补充复查修复

收尾再次 panic 时，原 worker 曾可能使用收尾异常重建失败字段，而重启路径使用已保存业务结果，造成两条路径不一致。现在共用 pendingFailureUpdates，从已保存结果生成终态字段；计数分类和错误样本也使用原结果。TestBreakerSettlementOnlyTerminalAttemptsJournalMySQL/auxiliary-panic 验证任务 error 和 obs 证据保留原业务失败。账号反馈保持及时执行，仅排在必要的结果持久化之后，不等待完成时间重试结束。
